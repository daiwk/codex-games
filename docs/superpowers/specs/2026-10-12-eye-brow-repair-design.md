# 三国角色眉眼局部修复（M1，v4）

## 已确认的方向

用户已同意：在保留赵云、马超脸型和人物风格的前提下，局部重绘眉眼，检查眼睑与头盔遮挡，必要时调整眼部网格。仍停留在 M1，不制作挂枪、IK、Godot 角色或战斗系统。

本方案是在此前保守修复方案之上的明确变更：允许在眼部引入新的绘制细节，而不是声称滤波能够恢复原本不存在的细节。原方案中“不使用生成式方法重绘五官”的限制，仅在用户此次批准的眉眼局部范围内解除。

## 当前证据

项目资源位于 `godot-games/3a-games/`，不是假设存在的 `assets/` 目录。

- 赵云脸部为 `tripo_part_52`；v3 已恢复原始面部图像 181 的 JPEG 字节。
- 马超脸部为 `tripo_part_29`；v3 已恢复原始面部图像 45 的 JPEG 字节。
- 两份 v3 的贴图均与原始资产逐图字节相同；网格、蒙皮和动画访问器均与 v2 相同。
- 已有相同相机、灯光和 Cycles 设置的原始法线回退、v2、v3 对照，以及 v3 单独面部渲染。单独面部仍显示模糊、缺少清楚瞳孔的眼部，不能仅把问题归咎于头盔阴影。
- v2 使用了错误的 UV V 方向，其填边覆盖了约 22% 的有效面部纹理；v4 不继承这项贴图处理。
- 现有报告未证明原始眼部具有足以直接使用的独立眼球、完整眼睑或清晰眉毛。是否需要添加或修改局部几何，必须依据进一步的网格与遮挡检查决定。

## 方案选择

1. **推荐：局部眉眼贴图修复，必要时补眼部几何。** 保留人物主体及脸型，先用贴图候选验证眼睛清晰度；只有贴图不能解决闭合眼睑、凹陷或遮挡时，才对该区域作可记录的几何修补。
2. **只调整灯光或锐化原贴图。** 最易保留原资产，但已有同灯光及独立面部对照表明，无法解决眼部信息不足，因此不作为交付方案。
3. **替换整张脸或重新生成人物。** 可能提供更完整五官，但会改变人物外貌和已有资产，不在本次授权范围内。

## 实现边界

### 眉眼绘制

- 使用内置 imagegen 编辑真实模型的面部参考视图，分别保留两个人物的比例、肤色和严肃武将气质。只增加自然的眉毛、眼睑及可辨认的深棕色虹膜和瞳孔，不改变鼻、嘴、下颌、脸型、头盔和身体。
- 生成图只作为局部纹理候选，不能直接用生成图替代真实 GLB 的验收渲染。
- 不直接让生成模型重排整张 UV 图集。通过实际几何与相机对应关系，将候选眼部内容投影或烘焙回原有 UV；眼部区域以外继续使用原始贴图内容。
- 保存输入、输出、提示词、投影区域和处理脚本。正确区分 glTF 与 Blender 的 UV 坐标方向，验证有效像素不被错误填边覆盖。
- 输出更高分辨率不能被描述为“恢复原始细节”。新增眉眼细节必须标注为重绘。

### 眼部几何与遮挡

- 先检查面部、眉眼附近及头盔前沿的实际三角面和深度关系，分别渲染完整头部、去除头盔的面部，以及灰模或无阴影底色视图。
- 首先保留原有几何；不为了让眼睛可见而整体抬高或缩小头盔。
- 如必须调整眼睑或添加眼球，仅修改眼部局部区域，新眼部结构跟随 `mixamorig:Head`。不替换真实人物主体，不改动其他身体部位或新增表情骨架。
- 不预先承诺网格数、顶点数和三角面数绝对不变：若新增眼部几何，报告须列出实际增量及蒙皮数据。原有动作名称、轨道、时长、骨架名称、层次和 inverse bind matrix 不变。
- 若眼部修补需要改动鼻、嘴、脸部轮廓或大面积头盔结构，则停止该分支并报告，不扩大授权范围。

## 验收

1. 全新 Blender 进程实际重新导入两份输出；报告导入错误、网格、三角面、材质、纹理、骨骼和动画数量。
2. 对比源文件哈希，确认原始三份 GLB 未修改；验证骨架和动画数据保留，以及眼部之外的修改范围。
3. 新眼部（若存在）权重合法、权重和为 1，跟随 Head；采样全部已有动画的关键姿态检查相对 Head 的位置稳定性。
4. 相同相机、灯光、曝光、渲染器下提供 v3/v4 正面、左右斜侧面、无阴影底色及全身构图对照。两只眼睛在正面近景应可辨认虹膜/瞳孔，眉毛应与肤色明确区分，不表现为闭眼或贴上去的粗黑条。
5. 每条现有动画至少渲染开始、中间和结束姿态的头部近景，检查穿插、眉眼漂移和异常遮挡；不以单帧静态效果图替代动画验证。
6. 检查缩小纹理和较远镜头下是否出现黑边、错位或明显消失；若使用新增眼部，检查侧面是否悬浮、穿出或脱离眼眶。
7. 如达不到自然、可辨认的眉眼效果，保留候选和证据但标记不通过，不把候选命名为已验收修复。
8. 不声称 Godot 导入、运行或战斗测试通过。本次没有进入 M2。

## 实施顺序及失败处理

先建立局部几何和 UV 对应证据，再生成纹理候选，回贴真实模型进行静态比较；根据比较结果决定是否需要眼部局部几何修补；最后输出并重新导入，执行动画、结构及远近视图检查。

若内置 imagegen 不可用或失败，说明限制，不擅自使用收费 API 或外部 CLI。若局部候选改变脸型、投影无法可靠对齐、或新增几何无法保持眼部自然，则回退该候选，继续保留 v3 为恢复点，并明确记录尚未完成的部分。

本文件是实施前的验收方案，不是修复完成报告。按 brainstorming 技能要求，书面方案需由用户复核后才开始重绘及网格修改。
