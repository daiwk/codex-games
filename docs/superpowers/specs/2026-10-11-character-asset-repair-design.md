# 三国武将角色资产保守完整修复设计

## 目标

基于 M1 检查结果制作赵云和马超的第二版派生 GLB，改善战斗动画中最明显的头脸错位、头盔漂移、黑色法线斑和局部接缝，同时保留人物现有外貌、骨架、动画和原始资产。

修复产物仅作为 M1 的资产修复结果，不包含挂枪、双手 IK、Godot 场景或战斗逻辑。原始 `zhaoyun_rigged_v1.glb`、`machao_rigged_v1.glb` 和 `zhaoyun_spear.glb` 不做修改。

## 输出

输出放在 `godot-games/3a-games/derived/m1/`：

- `zhaoyun_rigged_v1_repaired_v2.glb`
- `machao_rigged_v1_repaired_v2.glb`

修复脚本放在 `godot-games/3a-games/tools/`，验证报告和对照渲染放在 `godot-games/3a-games/reports/m1/repair_v2/`。脚本必须从原始 GLB 或已验证的法线回退副本重复生成相同结果，不能依赖未保存的 Blender UI 状态。

## 修复范围

### 材质和法线

第二版沿用 M1 法线回退策略，禁用人物当前异常的法线贴图引用。原法线图像继续保存在 GLB 内，便于后续重新烘焙或恢复。当前阶段不把低质量法线重新加工成最终法线，因为输入图中包含黑色、饱和红绿和错误方向区域，滤波无法可靠恢复其三维信息。

人物金属度和粗糙度维持原值，避免在没有统一灯光与 Godot 实测的情况下重做全部 PBR 外观。

### 头盔和面部权重

面部 Mesh 作为刚性头部结构处理，全部有效蒙皮权重转移到 `mixamorig:Head`：

- 赵云：`tripo_part_52`
- 马超：`tripo_part_29`

已由独立渲染确认的硬质头盔部件也转移到 `mixamorig:Head`：

- 赵云：`tripo_part_10`、`tripo_part_17`、`tripo_part_18`、`tripo_part_98`、`tripo_part_104`、`tripo_part_108`、`tripo_part_121`、`tripo_part_126`、`tripo_part_140`
- 马超：`tripo_part_16`

赵云颈部 `tripo_part_74` 和白色长缨 `tripo_part_2` 保持原有渐变权重。马超 `tripo_part_19` 同时包含硬质头盔后侧和长发，不做整件刚性绑定；先按顶点空间位置和现有 Head 权重识别硬质头盔区域，只把高于颈部且靠近头盔壳体的顶点转移到 Head，长发与披散部分保留原权重。若无法用稳定规则把二者分开，则保留该件原权重，并在报告中记录限制。

所有调整后每个顶点的权重和必须为 1，不允许零权重、越界骨骼或新增骨骼名称。动画轨道、静止姿态和 inverse bind matrix 不变。

### 几何接缝

接缝修复限定在头脸区域，并采用局部、可量化的方式：

- 识别面部边界与相邻头盔或颈部边界的最近点。
- 只对小于模型高度约 0.5% 的间隙尝试沿局部法线或最近点方向调整。
- 保留 UV、顶点数量、三角面索引和部件结构；不跨 Mesh 焊接，不全局合并顶点。
- 任何会改变正面轮廓、五官比例或造成三角面翻转的调整都跳过并记录。

此策略用于减少近距离可见的细缝，不宣称消除所有由独立分件造成的开口。服装、衣摆、头发和身体其他部位的开口不在本次范围内。

### 面部底色

不使用生成式方法重绘五官，以免改变赵云或马超的身份特征。对现有脸部底色执行保守处理：

- 保持原 UV 和脸部纹理内容。
- 对脸部有效 UV 岛内部做轻度色彩去噪和局部对比度恢复。
- 对黑色透明背景或未使用区域不做扩散到有效像素的处理。
- 在 UV 岛边缘生成有限像素的颜色延展，减少双线性采样与 mipmap 引起的黑边。
- 输出前后纹理和面部渲染对照；若锐化放大压缩块或改变五官，则回退到只做边缘延展。

原 256×256 的有效脸部信息不足以恢复新的皮肤细节。允许以更高分辨率保存处理结果来改善采样，但报告必须说明这是重采样与边缘处理，不是新增真实细节。

## 生成流程

1. 从原始 GLB 导入 Blender，并核对源文件 SHA256。
2. 禁用异常法线贴图引用。
3. 按已确认的 Mesh 和顶点规则校正头脸权重。
4. 测量并处理满足阈值的局部接缝。
5. 处理脸部底色和 UV 岛边缘。
6. 导出到新的 `*_repaired_v2.glb`，不覆盖任何已有文件；同名且内容不同的文件应拒绝覆盖。
7. 在全新 Blender 进程中重新导入修复副本，执行结构、动画和渲染验证。

## 验证标准

每个修复副本必须满足：

- Blender 独立重新导入成功。
- Mesh 数、三角面数、骨骼名称和层次、9 条动画名称及长度保持不变。
- 动画轨道数据和 inverse bind matrix 与原始资产一致。
- 所有顶点权重和为 1，无零权重和越界 joint。
- 面部和硬质头盔在全部 9 × 120 个关键姿态中相对 Head 的刚性偏差接近浮点误差。
- 被判定为柔性的颈部和头发没有被整体锁死到 Head。
- 原始黑色法线三角斑不再出现。
- 修复前后正面、侧面，以及每条动画的开始、中段和结束都有对照图。
- 灰模对照不出现新的轮廓塌陷、三角面翻转或明显穿插。
- 原始三份 GLB 的 SHA256 与 M1 报告一致。

验证将覆盖结构和动画采样，但不会替代 Godot 导入、第三人称镜头和实际战斗运行测试。Godot 侧验证属于后续里程碑。

## 失败处理

每项修复独立应用并记录。如果局部接缝移动或纹理锐化不能通过渲染对照，则只回退该项，保留已通过的法线和权重修复。脚本不得修改原文件，也不得删除现有 M1 法线回退副本。

马超后侧头盔与长发若不能可靠分离，将保留原权重并列为后续手工拆分任务；不以整体刚性绑定换取静态画面改善。

## 完成条件

两份 `repaired_v2.glb`、可重复运行的生成脚本、机器可读验证结果和修复前后对照图全部生成，所有结构与权重检查通过，并在报告中明确说明未能安全自动修复的部分。完成后仍停留在 M1，等待用户确认是否进入 M2。
